# Booking context and availability, 9 November 2026

Status: DONE implementation and configured-database installation. VERIFIED: 127 application tests, standalone typecheck, production build and read-only local HTTP checks.

The saved-look load effect previously cleared serviceName, and the availability request requires that field. Thus selecting a stylist/date alone could not load slots for a look. The old slot generator also used a midnight-based half-hour grid. The corrected form retrieves a database preset association, prefills category/service and current price, and preserves a manual change on date/stylist refresh. Missing associations retain manual selection.

Migration 0011 adds salon_services, preset_services and a normalized one-to-one appointment_services identity record. Stable IDs bootstrap from the existing catalog; the first supported preset association is its default service, while other matching services remain selectable. Customer booking resolves canonical name/type/price from the database even when request names or prices are forged. The service identity and appointment are written in the same database function transaction. Historical appointment rows are not rewritten.

Availability now starts at each working interval, advances by exactly 90 minutes, jumps to an overlapping reservation's 90-minute end, and omits past starts. It respects work status, qualifications, working-hour bounds and pending/confirmed reservations; cancellation releases time. Exact 90-minute conflicts also apply to legacy starts and database scheduling triggers, replacing the previous minimum-90 policy for longer stored rows without rewriting them. Stylist locking and transactional rechecks remain intact. Time buttons supplement the accessible select, with selected/unavailable states, loading, retry and empty results.

Tests include the exact 09:00/10:30/12:00/13:30/15:00 working-day sequence; an off-grid 10:00 booking followed by 11:30; independent staff, past times, cancellation, work status and concurrent requests; database-price changes and forged client fields; saved-preset prefill/manual override; and existing private look, payment and archive behavior. Regression fixtures were updated to use the new grid and database price authority. No model, dataset, prompt or generation/runtime file changed; all 265 protected hashes match.

The configured database migration initially failed and rolled back; its retry succeeded. Exact guarded before/after fingerprints preserved 20 users, 9 client profiles, 31 appointments, 77 generation rows, 18 inventory rows, 15 specialties and zero review/product-usage/inventory-transaction rows. No account seed, appointment creation or live verification mutation was performed. The local built app returned HTTP 200 for 63 services and HTTP 200 with five slots/duration 90 for a service-ID availability request. Browser viewport acceptance and website deployment remain unverified.
