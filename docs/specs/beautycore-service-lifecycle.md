# Appointment no-shows and service controls

Status: CONFIRMED user scope, 9 November 2026. Preserve protected AI resources and existing customer, appointment and financial records.

Extend the existing appointment statuses with in_progress and no_show. Assigned stylists or administrators may record arrival and start within 30 minutes before the scheduled time and before the 30-minute grace deadline; recorded arrival allows a later start. Start records actual start/arrival time. Manual no-show is allowed from the scheduled start, with a reason and explicit confirmation, only when neither arrival nor start was recorded. No-show cannot be started, completed, deleted or edited through ordinary appointment controls. Admin restoration requires a reason, future time and fresh availability/qualification checks.

Stop Service offers completion through the existing product/completion workflow, no-show, cancellation under existing rules, or Other with an explanation and unchanged status. Require confirmation before committing an outcome. Keep actual timing separate from the scheduled appointment, record actors and maintain activity history. Legacy authorized direct completion remains supported for existing service-record workflows; no-show completion is rejected.

A database function processes confirmed assigned appointments whose scheduled start plus 30 minutes has passed, excludes arrived/started records, and rechecks under stylist/row locks. Duplicate runs must not duplicate no-show events. A backend worker runs every ten seconds with npm start/npm run dev, with a standalone worker:no-shows command and catch-up before appointment/availability reads and booking. Do not retroactively process overdue appointments predating policy installation. No frontend timer decides status.

Confirmed reservations remain exactly 90 minutes. A running service retains a rolling near-term hold while it remains active, protecting ongoing work without blocking unrelated future dates. A no-show/cancelled reservation releases its time. For a released current slot, start at the next future whole minute, fit a full 90 minutes inside working hours and skip conflicting reservations. Visible pages refresh every ten seconds and immediately after a local status action. Suspended hosts catch up on return; uninterrupted wall-clock processing requires the web process or standalone worker to remain running.
